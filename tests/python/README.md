## 验收标准

**大关 1 / 大关 2**（每关都要满足）：
1. **NoRW = 无**：当普通推箱子解不开。
2. **MIN ≥ 1** 且与 `par_rewinds` 一致，`rewind_budget ≥ par_rewinds`。
3. **回放=通过**：参考解按项目记法（`U/D/L/R`、`P<节点>`、`B<箱号>:<节点>`）能跑通。

**大关 3**（每关都要满足）：
1. **回放=通过**（参考解含 `P<i>` / `B<k>:<i>` 跨图回溯也能跑通）。
2. **跨图搬运**：至少一个箱子的目标**全部在别的图上**（证明必须用传送门）。
3. 不强制"无回溯无解" —— 生成器构造出的关卡本身可直推，但不用回溯的路会长得多（第 25 关 15 步 vs 38 步）。

改完必须回项目跑 `solve_test.gd`（S1~S30 用同一批参考解做端到端验证）+ `room_test.gd`（多地图/传送门/颜色 20 项）。

## 四条设计铁律（血泪教训）

1. **走廊尽头必须真的封死**：箱子推到尽头后，若玩家能从别的格子绕到箱子另一侧，他就能把箱子推回来 —— 这一关就不再需要回溯。判定方法：箱子终点东侧是墙/边界，且玩家去不到那一格。
   **走廊上下也必须是真墙**：留一整行地板就等于留了绕行路（大关 2 第一版就是这么废掉的）。
2. **一格宽走廊里放两个前后相邻的箱子 = 直接死局**（前箱推不动、后箱推不动）。要做双箱，就把第二只放进侧屋。
3. **单门口运箱 = 必然死局**：一关里若门 A 是唯一的一对，箱子被推进 A 后就堵在对面那格，玩家再也进不去。**运箱的关卡必须至少两对门**（一对给箱子、一对给玩家）。
4. **随机撒点几乎必然无解**：开放地图上随机摆箱子，可解率接近 0（实测 170 组 0 命中）。要生成关卡必须**构造式**——先按力学反推一个一定可解的摆法，再加固/加箱制造难度。

快速搜索用的是「动作生成用完整状态、已访问只看 (玩家, 箱子, 剩余次数)」的折叠法，速度比精确 BFS 快几十倍但**不完备**；找到的解一律用 `replay()` 精确复核过才可信。**注意**：`min_rewinds` 报的 k 是"在步数上限内需要几次回溯"，不等于"不用回溯无解" —— 想确认后者必须另外跑 `solve_no_rewind()`。

## 第三版（当前主力）：`rb_gen5.py` —— 多母题 + 大地图 + 强制回溯

```bash
python rb_gen5.py          # 15 关一键自检（16~30 关）
python rb_gen5.py -v       # 同时打印地图与参考解
python rb_apply_ch5.py     # 装机（保留 1~15 关，自动跑 solve_test 并回滚）
```

里面有三个可复用的东西：

| 函数 | 作用 |
|---|---|
| `no_rewind_solvable(w)` | **精确**判定"完全不用回溯能否通关"。玩家位置按**可达区域归一化**（经典 Sokoban 解法）+ 查表实现 → 比 `rb_world.solve_no_rewind()` 快上千倍，而且**完备**（旧版每状态存整份动作列表，2 箱大图必爆） |
| `route(w, a, b, blocked)` | 走位 BFS，**正确建模传送门**（踩上去就落到对面，落点不再连锁传送） |
| `build_solution(w, anchors)` | **构造式参考解**：按母题结构拼动作，不依赖慢搜索 |

两套母题：
- `core_a`（16~20 关）**借道**：1 格宽走廊 + 箱子 + 玩家在左 + 尽头是墙 → 只能回溯箱子（1 次）。
- `core_b`（21~30 关）**双借道**：两条平行走廊各一只箱子 → **必须回溯 2 次**，两箱对色。

**设计取舍：画布大、可行格少。** 画布最大 35×23，但可走格只有 54~356，
其余是**封闭的"建筑"**（`decorate()` 只挖内部、外面仍是墙 → 玩家进不去，纯装饰）。
不可达的格子对求解器是零成本的，可以随便加来撑场面。

> ⚠️ 密室矩形**不能和走廊的行重叠**（两张图共用坐标系，会把走廊那几格从图 0 挖走）。
