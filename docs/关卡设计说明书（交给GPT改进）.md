# Reverse Box：逆时推箱 —— 关卡设计说明书（交给外部模型改进用）

> **用途**：把现有的机制规则、关卡格式、以及 10 个关卡的设计细节完整交代清楚，交给外部模型（GPT）重新设计关卡。
> **当前诉求**：现有 10 关**太简单**，而且**第 2~8 关基本是同一个套路**。需要**难度骤增**、**地图稍大一点（但别太大）**、每关的思考维度要不一样。
> **重要**：改关卡时**不要改玩法机制**，机制已经定稿（见第 3 节）。只改关卡布局与资源配置。

---

## 1. 游戏是什么

一款 2D 像素风"推箱子 + 时间回溯"解谜游戏（Godot 4.5 实现）。核心不是"可撤销的推箱子"，而是：

> **可以让特定的对象（玩家，或某一个箱子）单独回到它自己过去位置的推箱子。**

玩家要思考的是：

- "现在的我该留在哪？"
- "这个箱子该回到它过去经过的哪个位置？"
- "谁需要回溯？回到哪一个过去，才能创造出正常推箱做不到的推动条件？"

---

## 2. 基础规则（推箱子部分，不可改）

### 2.1 世界

- 地图是**离散方格**。地形只有两种：**墙**、**地板**；另有**目标点**标记在地板上。
- 场上元素：**恰好 1 个玩家**、**若干箱子**（数量必须等于目标点数量）。
- 一次移动只能上下左右**走一格**。

### 2.2 移动判定（一次按键只有三种结果）

| 情况 | 结果 |
|---|---|
| 目标格是地板且没有箱子 | 玩家走过去 |
| 目标格有箱子，且箱子后面那一格是空地板 | 箱子被推过去一格，玩家站上箱子原来的位置 |
| 目标格是墙，或目标格有箱子但箱子后面是墙/另一个箱子 | **整次移动作废：玩家和箱子都原地不动**（不会出现"人动了箱子没动"） |

**箱子只能推、绝对不能拉。** 想让箱子往左走，玩家必须绕到它的右边。

### 2.3 通关条件

**所有目标点都被箱子占住**即通关。玩家站在哪里不影响通关。

## 3. 核心机制：对象独立回溯（不可改）

### 3.1 每个对象都有自己的时间轨迹

- **玩家**有一条轨迹；**每一个箱子**也各自有一条轨迹。
- 轨迹记录的是**该对象真实经过过的格子**（起点为轨迹第 0 个节点）。位置没变就不记录。
- 因此：**箱子不能回到它没去过的格子，玩家也不能。**

### 3.2 回溯只作用于"被选中的那一个对象"

**这是整个游戏的根：**

- **回溯玩家** → 箱子全部保持现在的状态，纹丝不动
- **回溯某个箱子** → 玩家保持现在的位置，其他箱子也不动

由此产生本作的核心公式：

```
玩家现在的位置 + 箱子过去的位置 = 正常推箱做不到的推动条件
玩家过去的位置 + 箱子现在的位置 = 正常推箱做不到的推动条件
玩家过去的位置 + 箱子过去的位置 = 高阶谜题（还需要正确的回溯顺序）
```

### 3.3 回溯到"哪个位置"由玩家选

- 打开回溯面板 → 选择对象（玩家 / 箱子 A / 箱子 B …）→ 在该对象的轨迹里挑一个**历史节点** → 确认。
- **只能回到严格早于"当前"的节点**（当前那一格本身不算"过去"，不能选）。
- 回到第 k 个历史位置后，**该对象在这之后的那段轨迹会被丢弃**（相当于"这个对象的未来被剪掉了"）。

### 3.4 回溯的合法性（公平性核心）

回溯目标格**必须当前空闲**，否则该节点不可选（面板里变灰）：

- 玩家回溯：目标格不能是墙、不能有箱子
- 箱子回溯：目标格不能是墙、不能有玩家、不能有别的箱子
- 回溯**不允许穿墙、不允许凭空生成/复制箱子、不允许让箱子穿过另一个箱子**
- 回溯**不会自动完成目标点**（只有箱子真的落在目标点上才算）

### 3.5 回溯资源

- 每关给一个**回溯次数**配额：**玩家回溯一次扣 1，箱子回溯一次扣 1**（不分对象类型，统一扣 1）。
- 这个资源**不是"容错次数"，而是"你能改变几次对象的时间状态"** —— 玩家完全可能一次错误都没犯，仍然要主动回溯。
- 配额可以为 1、2、3…（关卡越难，越倾向于给很少的次数，逼玩家规划）。
- **评级**（不用改，但要考虑进去）：用掉的次数 ≤ 设计最优 = S；多 1 次 = A；多 2 次 = B；更多 = C。
  **所以每关需要一个"设计最优回溯次数"（par）**，请在设计时给出。

### 3.6 其他已定稿的规则

- 每关可以**立即重开**（不消耗资源、清空所有轨迹），玩家可以随便试错研究。
- 回溯表现是短暂的时间压缩效果（闪屏 + 残影 + 涟漪），**不做长动画**。
- 玩家走过/箱子经过的地方会留下**淡淡的时间痕迹**（视觉提示，不是玩法）。

## 4. 关卡数据格式与硬约束（照着填就能用）

### 4.1 布局符号

| 字符 | 含义 | 字符 | 含义 |
|---|---|---|---|
| `#` | 墙 | `$` | 箱子 |
| `.` | 地板 | `&` | 箱子（且在目标点上） |
| `*` | 目标点 | `@` | 玩家 |
| `+` | 玩家（站在目标点上） | | |

### 4.2 硬约束（不满足会直接被自检判错）

1. **每一行等宽**（用空格补齐也算错，请直接写成等宽）
2. **整张地图最外一圈必须全是墙**（`#`）
3. **恰好 1 个玩家**（`@` 或 `+`）
4. **箱子数 == 目标点数**
5. 坐标约定：**x 向右、y 向下**，从 0 开始计
6. **箱子编号按"行优先"顺序**（先上后下、同一行先左后右）—— 参考解里会用到箱号

### 4.3 每关需要的字段

| 字段 | 说明 |
|---|---|
| `name` | 关卡名（中文，带序号） |
| `rewind_budget` | 本关可用回溯次数 |
| `par_rewinds` | 设计最优回溯次数（用于 S/A/B/C 评级） |
| `hint` | 一句话提示（只在教学关显示；其他关留空） |
| `layout` | 文本布局（字符串数组） |

## 5. 关卡设计的红线

### 5.1 每一关都必须满足"不用时间机制则无解"

这是最重要的一条，也是验收方式：

> **把这一关当成普通推箱子来解 → 必须无解。**
> **用上独立回溯 → 必须存在一个解。**

也就是说，每关都要能明确回答："**如果不回溯，为什么这个动作不可能完成？**"

### 5.2 不允许"为了逼玩家按回溯而先让玩家死一次"

反面例子（**不要这样设计**）：走错 → 死局 → 只能按 R 救回来。
那还是把回溯当悔棋用。应当设计成：

```
普通走法：可以继续玩，但永远无法完成最终条件
聪明走法：主动利用回溯改变对象的位置
最终解  ：只有理解了时间机制才能完成
```

### 5.3 不要靠"堆箱子数量"制造难度

难度应该来自**时间关系**（回到谁、回到哪个位置、按什么顺序回），而不是"1 箱 → 2 箱 → 3 箱 → 4 箱"。

### 5.4 不许引入与核心机制无关的新东西

不要加：过去分身、平行时间线、多玩家、时间复制、RPG 属性、技能树。本作保持 **单玩家 + 每个箱子各自一条轨迹 + 独立回溯**。

## 6. 现有 10 关逐关拆解

> 下面每关都给出：布局、元素坐标、设计意图、参考解、为什么必须回溯、**以及我认为的问题**。
> 参考解记法：`U/D/L/R` = 上下左右移动；`B<箱号>:<节点>` = 把第 <箱号> 个箱子回溯到轨迹里第 <节点> 个位置；`P<节点>` = 把玩家回溯到轨迹第 <节点> 个位置。

### 共同的"地图骨架"

现有 10 关里除了第 1 关，其余全部是同一个骨架：

```
左屋  +  1 格宽的长走廊  +  右屋（右屋在走廊中段上方开一个口连通）
```

- 走廊**只有 1 格宽**，箱子在走廊里只能沿走廊平移，**永远不能转弯**
- 走廊右端是**死位**：箱子被推到最右端就再也推不回来（要推回来得站在墙里）
- 右屋里放 1~2 个箱子，只能从走廊里**往上推**到它们的目标点

**所有关卡的套路都是**：把走廊里的箱子往右推过头 → 玩家趁机走到右屋把右屋的箱子推上去 → 再把走廊里的箱子**回溯**回它经过的某个格子。

### 第 1 关 · 推箱子（教学，不需要回溯）

```

#.....#      玩家 (3,5)
#..*..#
#.....#      rewind_budget = 1
#..$..#      par_rewinds  = 0
#..@..#
#######
```

- **意图**：教移动、推箱、目标点；顺便让玩家注意到地上淡淡的时间痕迹
- **参考解**：`U U`
- **为什么不需要回溯**：这一关本来就不设红线，是唯一允许"纯推箱"的关
- **问题**：没问题，但只有 2 步，几乎不算一关

### 第 2 关 · 让它回到过去

```
########     箱子 A (5,2) → 目标 (5,1)    玩家 (1,3)
#..#.*.#     箱子 B (2,3) → 目标 (4,3)
#..##$.#
#@$.*..#     rewind_budget = 2 / par = 1
########
```

- **意图**：第一次教回溯。箱子 B 必须被往右推（玩家要借道走廊去右屋），推过头就卡在走廊尽头 `(6,3)` 出不来 → 必须把 B 回溯回它经过的 `(4,3)`

## 7. 现状问题清单（这就是希望被改进的地方）

1. **难度太低、曲线几乎平的**：10 关里 9 关的最优解都是"走几步 + 1 次回溯"，最短解 2~12 步；没有任何一关需要连续规划。
2. **套路重复**：第 2、3、4、5、7、9 关是**同一个谜题**（把走廊箱子推过头再送回它经过的格子），第 6、8、10 关是**同一个谜题**（多了右屋两箱的顺序推）。
3. **地图大小原地踏步**：8×5 用了 7 关，10×5 用了 2 关；没有真正的"中型地图"。
4. **"选对象"是假的**：没有任何一关需要真正判断"该回溯玩家还是该回溯箱子"，也没有一关需要判断"箱子 A 还是箱子 B"。
5. **没有"回溯顺序"关**：先回玩家 / 先回箱子 没有区别，设计文档里"顺序即谜题"的目标完全没实现。
6. **没有"轨迹利用"关**：不存在"必须先让某个对象经过某个位置，以后再把它送回那里"的关卡。
7. **没有"玩家回溯必需"关**：所有解都落在回溯箱子上。（技术上很难：纯推箱规则下玩家走过的路一般还能再走回去；需要利用"箱子被卡在**唯一通道**上"的结构 —— 走廊**弯角**处卡死的箱子可以彻底封路。）
8. **资源给得太宽松**：第 5 关给 3 次只要 1 次，第 2、3、4、7、8 关给 2 次只要 1 次。资源不紧，时间操作就没有分量。
9. **教学关太少**：只有第 1 关是纯教学，第 2 关就要求玩家自己发现"回溯只动一个对象"。

## 8. 重做目标（请在满足这些前提下来设计）

### 8.1 总体

- **难度要"骤增"**：不要再做 10 关同一难度的东西。建议明确分段：
  - **入门 2~3 关**：只教机制（怎么开面板、回溯只动一个对象、箱子能回到过去）
  - **进阶 3~4 关**：每关引入**一个全新的思考维度**
  - **高阶 3~4 关**：组合维度，且**回溯次数很紧**（配额 == 最优）
- **地图尺寸**：建议在 **8×6 ~ 13×9** 之间。不要超过 13×9（手机上会缩小到看不清）；也不要再出现"7 关都是 8×5"。
- 关卡数量 **10~12 关**都行（原来 10 关，可扩到 12）。

### 8.2 每关必须引入一个新维度（至少覆盖这些）

请至少覆盖下面这些"维度"，**一关一个**，不要重复：

| 维度 | 说明 |
|---|---|
| A. 玩家回溯入门 | 只回溯玩家，箱子不动 —— 让玩家发现"回溯可以只改变我自己" |
| B. 玩家重新获得站位 | 玩家把自己走丢了：**能继续玩，但再也无法从正确方向接近箱子**，只能用玩家回溯（或箱子回溯）拿回站位 |
| C. 箱子回溯入门 | 玩家位置正确、箱子位置错误，只能箱子回溯 |
| D. 二选一 | 同一个谜题里"回溯玩家"和"回溯箱子"都能做，但只有一个能通向解（另一个会让局面变死） |
| E. 多箱识别 | 两个箱子轨迹不同，必须判断**回溯哪一个箱子** |
| F. 双回溯 | 必须"玩家回溯一次 + 箱子回溯一次"才能完成（本作核心机制的完整组合） |
| G. 回溯顺序 | 先回 A 后回 B 能过；先回 B 后回 A 必失败 —— **顺序本身是谜题** |
| H. 诱导错误 | 普通推箱思维看起来完全正确（箱子推到了目标附近），但最后发现**没有可用的推动站位**，必须回到过去 |
| I. 资源管理 | 配额极紧（== 最优），玩家要提前规划"哪一次给玩家、哪一次给箱子、哪一步必须保留" |
| J. 轨迹利用（箱子） | 箱子必须**先经过**某个关键格（即使当时看起来是"推错"），之后再回溯到那一格 |
| K. 轨迹利用（玩家） | 玩家必须先经过某个关键站位，之后走远，最后回溯回去完成关键推动 |
| L. 双轨迹 | 玩家与箱子都要提前经过指定区域，最后各回各位，组合出最终推动 |

**注意**：维度 J/K/L 的关卡里，玩家的行为顺序是"先故意做一件事，再回溯利用它" —— 这正是设计文档里"回溯不是容错、而是主动改变时间状态"的体现。

### 8.3 每关还要考虑

- **提示文案**（`hint`）：入门关写一句，进阶/高阶关建议留空，让玩家自己发现。
- **回溯配额**：进阶关建议 == 最优（没有浪费空间）。
- **约束提醒**：仍必须满足"不用时间机制则无解"（第 5.1 节）。

## 10. 可用的"零件"素材库（组合这些来造关卡）

这些结构在现有实现下**已经验证可用**，可以放心组合：

| 零件 | 效果 |
|---|---|
| **1 格宽走廊** | 箱子在里面只能沿走廊平移，**永远无法转弯**；玩家也无法绕过箱子 |
| **走廊尽头的死位** | 箱子推到头（前方是墙）就再也推不回来 → 逼出"箱子回溯" |
| **1 格宽的拐弯（弯角）** | 箱子推到拐弯处会**彻底卡死**（四个方向的推动都不可行）→ 可以当"永久路障"用，能把玩家和某片区域隔开 |
| **1×1 死洞（nook）** | 箱子推进去就出不来 → 常用来当"目标点"，或当"永久占位"挡掉一个站位 |
| **右屋 / 侧屋** | 只能从走廊某一格拐进去的小房间；里面的箱子通常只能被"从走廊里往上推" |
| **双箱并排** | 形成"推不动"的墙，或者制造"必须选一个回溯"的抉择 |
| **目标点放在走廊里** | 箱子会**经过**目标点但也可能推过头 → 天然产生"回溯回那一格"的需求 |
| **墙边/角落** | 箱子贴墙后只能沿墙推，贴角则卡死 → 制造"推错就回不来" |

**特别注意"弯角"零件**：它是目前唯一能在纯推箱规则下**永久封路**的结构（因为弯角处的箱子四个方向都推不动）。想设计"玩家被关在外面，只能靠回溯自己回到过去"的关卡，就用它。

## 11. 我这边怎么验收（供你自查时参考）

每关我都会跑两件事：

1. **无回溯可解性检查**：把这一关当普通推箱子做 BFS 求解，**必须返回"无解"**；返回"可解"就说明这一关不需要时间机制，会被打回。
2. **参考解验证**：把你给的参考解按上面记法跑一遍，**必须通关**，并且检查实际回溯次数是否等于你声明的 par。

所以请尽量保证：
- 布局**等宽、外圈全墙、箱数 == 目标数、恰好 1 个玩家**
- 参考解**每一步都合法**（别出现"推不动却仍写在解里"的动作）
- 回溯操作的目标格在你写的那个时刻**是空的**（不能回到玩家或别的箱子占着的格子上）

## 12. 可选扩展（需要先拍板，默认不做）

如果以后想让机制更有层次，可以加一种**"回溯不恢复"的一次性元素**（一次性开关 / 单向门 / 深坑）：它不会因为回溯而复原，于是"回溯"就从"回退"变成一种**时序工具**（例如：先踩开关开门，再回溯把自己送回门这边）。
**这一条默认不做**，除非用户明确要加；请在改进关卡时**只使用现有机制**。
